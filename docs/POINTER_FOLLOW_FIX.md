# 指针与滑块跟手修复（2026-11-09）

## 复现及根因

1. 准星中心点虽使用最新指针，主线及读数却通过45ms指数平滑跟随。旧版从(100,350)快速移动到(600,420)后，检查时主线仍在约(255,372)，中心点已在600，产生明显错位。
2. 平台控件在拖动中停止事件冒泡，准星的document冒泡监听收不到移动事件，因此捕获拖动期间可能停在旧位置。
3. 平台切换动画在85ms后才开始收束；动画中再次抓取时，命中识别使用仍在移动的视觉边界，且会沿用拉长尺寸，导致当前选中项可能无法立即拖动或可移动距离受限。原4px阈值还使第一段移动没有视觉反馈。

## 修复

- 准星主线、中心点、坐标读数在同一pointermove中使用同一最新坐标，移除位置平滑；窗口缩放刷新读数。漂浮圆球锁定仍由原rAF跟踪，不改物理或视觉构图。
- 使用只读的捕获阶段监听，不拦截输入，即使控件阻止冒泡也持续跟手；触摸、禁用、隐藏及reduced-motion仍隐藏准星并停止跟踪。
- 当前选中平台可直接抓取，按下即停止旧动画并恢复标准分段宽度；拖动逐事件更新，从第1px即显示位移。2px阈值仅负责点击/拖动判定。
- 切换交接等待85→32ms，集中弹簧参数调整为stiffness1800/damping76。惯性吸附、边缘压缩、取消还原及键盘支持保留，拖动阶段不使用弹簧插值。

## 验证

- Chrome新增12项通过：旧版6项基线中4项失败，修复后对应检查全部通过。覆盖即时准星/读数、动画中重新抓取、首像素移动、捕获期间准星、连续反向、失焦取消、实际CDP触摸移动/取消和无页面错误。
- 连续反向的滑块位置误差0px，准星误差约0.004 CSS px（小于0.1px容差，浮点变换精度）。这验证事件和渲染状态一致，不代表测量了硬件输入至屏幕发光的时间。
- 三平台35项、准星10项、字体/坐标15项回归通过；旧通用回归仍54通过/8个相同历史词库基准/管理链式断言失败，未标为通过。
- macOS Safari原生拖动Google→bilibili成功，完整页面及准星/坐标落点已查看；未进行Safari精密延迟计时。移动为Chrome触摸模拟。Edge、移动真机和高刷新率硬件未实测。
- 第一次并行浏览器启动的准星回归超时；单独重跑完成并记录实际结果。

运行方式与现有测试一致：`PLAYWRIGHT_MODULE=/path/to/playwright node tests/pointer-follow.cjs`；`TEST_URL`可指向正式站。具体数值及旧版基线见 `POINTER_FOLLOW_RESULTS.json`。
